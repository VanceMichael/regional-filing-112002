# 联合数据登记的确认页代办的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。先执行 `npm ci`，再执行 `npx playwright install chromium` 准备 Chromium。

执行 `npm test` 检查合成来源和浏览器页面。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

服务地址下的 `/filing` 为联合登记受理表，`/filing/receipts` 为递交查询。跨区选择会刷新可见表单分支与签署确认格。新递交先进入处理中；推进来件阶段后查询页可显示受理结果。模拟受理记录存在服务进程内，重启可清空本地练习数据。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/intake` | participants 中每行给角色、门户统一编号和来件称呼。fingerprint 由委托方发出，用来绑定签署。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。

## 录入代办（`agent/`）

代办只通过浏览器（Playwright）操作门户，不直接调用 `/filing/submit`。本地状态默认写入 `./.agent/state.json`（已 gitignore），可用 `--state` 或 `AGENT_STATE` 改位置；门户地址用 `--base` 或 `PORTAL_URL`。

| 命令 | 作用 |
| --- | --- |
| `npm run agent sync` | 分页拉取当前阶段可见来件，登记到本地（不动草稿与回执） |
| `npm run agent list` | 先与回执页对账，再列出每份资料的状态、可安全执行动作、阻塞原因 |
| `npm run agent draft <case/fingerprint>` | 只按 `delegates` 授权起草并保存草稿，不签署、不递交 |
| `npm run agent edit <key> <field> <value>` | 登记经办人对草稿的人工修改，重办时保留且不被覆盖 |
| `npm run agent submit <key>` | 无阻塞才网页递交，只点击一次；409/在途/已受理一律不重复交 |
| `npm run agent recheck` | 重开时先对账同一次递交的归属与状态 |
| `npm run agent run` | 同步后逐份处理：能交的交，不能交的存草稿并列出阻塞 |
| `npm run agent receipt <受理号>` | 按受理号反查当时各角色确认的字段集合、声明与材料版本 |

### 安全规则如何落地

- **同名机构不靠简称猜**：两个「远帆」选项（ORG-02 / ORG-03）只按 `<option value>` 的统一编号选择并回读；来件编号在门户缺失且简称同名时报「角色歧义」交经办人。
- **分支以门户实际渲染为准**：切换登记地区后等待页面分支名刷新，重新读取可见字段集与签署格再生成计划；门户实际分支与归属地应得分支不符即停止。
- **声明不跨分支、不跨材料复用**：勾选签署格要求声明同时匹配「当前分支 + 页面显示字段集合 + 材料指纹 + 角色机构」。例如 intake-2 的国内-R1 声明在跨区-R2 页面判为不可用，跨区联络人又缺签署，该单只存草稿。
- **只做授权代填**：`delegates` 之外的字段不填；没有有效声明的签署格绝不勾选，不替未授权角色新签。
- **独立页面不串单**：每份资料开全新浏览器页面，签署勾选发生在最后一次分支渲染之后，并反向确认没有计划外勾选。
- **递交生命周期**：点击前先查回执索引；202 仅代表处理中，本地记在途，重开先 `recheck`，回执未确认归属前禁止重复交；门户 409 时绑定其回执号。
- **退回补正**：退回凭据（受理号、已受理字段）继续有效，原 `case/fingerprint` 键禁止重交；补正材料以新指纹、新确认的申请分支另行递交（如 D-22/A-29 走跨区-R2）。
- **人工修改**：经办人改过的草稿字段标记为 `human` 并保留，无冲突字段继续沿用；冲突、缺失签署、角色歧义均列入阻塞，退回经办人处理。
