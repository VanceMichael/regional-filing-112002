# 联合数据登记的确认页代办（本地演练）

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。演练分两部分：

- **来源服务 + 演练门户**（`source-server.mjs`、`portal.mjs`）：门户只能通过网页操作，含机构选择、按归属地刷新的确认格、受理后才能查到的回执页。
- **录入代办**（`agent/`）：通过真实浏览器驱动门户，按来件策略填草稿、判断可安全执行的动作、对账回执。代办不会代替未授权角色作出新的签署。

## 本地运行

使用 Node.js 22.23.4。先执行 `npm ci`，再执行 `npx playwright install chromium` 准备 Chromium。

执行 `npm test` 检查合成来源、浏览器页面、代办策略与端到端流程。执行 `npm start` 启动来源与门户，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

服务地址下的 `/filing` 为联合登记受理表，`/filing/receipts` 为递交查询，`/filing/receipts/<回执号>` 为回执详情（含受理时按各角色确认的材料快照）。跨区选择会刷新可见表单分支与签署确认格。新递交先进入处理中；控制员评审后查询页才显示受理或退回结果。模拟受理记录存在服务进程内，重启可清空本地练习数据。

## 来源接口

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/intake` | participants 中每行给角色、门户统一编号和来件称呼。fingerprint 由委托方发出，用来绑定签署。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。`next` 为下一页偏移，末页为 `null`。

控制员通过 `POST /control?stage=2` 切换回放阶段，服务保留更早已可查的记录。门户评审通过 `POST /filing/review?receipt=SL-101&decision=accept|return&reason=...&retain=title&retain=count` 完成；退回时 `retain` 列出仍有效、无需补正的字段。回执索引与详情支持 `?format=json`，页面同时内嵌等价的机器可读数据，代办只读取网页不直连内部接口。

## 代办安全边界

代办的每份资料决策（`agent/policy.mjs`，纯函数可单测）遵守：

1. **机构歧义**：法务清单写简称而门户存在同名单位（如两家「远帆」ORG-02/ORG-03）时，只按来件统一编号选定，绝不按名称猜；编号不在门户目录则阻塞。
2. **分支与签署**：归属地切换后确认格字段集合变化。签署必须同时匹配角色、当前分支名、材料指纹（版本）且字段集合与确认格完全一致；同名声明跨分支或跨指纹一律不可复用，缺签署只报阻塞，代办不自行勾选。
3. **授权字段**：只填来件 `delegates` 清单内的字段；门户必填而来件缺值、或字段未授权都报阻塞。草稿只填字段，不碰任何签署框。
4. **页面隔离**：每份资料用全新页面办理，递交前回读归属地、分支、机构、字段值与勾选框；发现上一单残留（含签署勾选）立即阻止。
5. **人工修改**：经办人手工改值通过 `edit` 登记；未冲突字段照常保留，冲突字段不覆盖并转为 `HUMAN_CONFLICT` 阻塞，连同缺失签署、角色歧义一起交回经办人。
6. **递交对账**：点击递交后可能只显示「处理中」，关页不代表没送到。重开先以门户回执索引判定同一次递交的归属与状态；本地有递交记录而索引暂不可查时保持等待、禁止重交。门户确认已接收的材料返回 409，代办不重复交。
7. **退回补正**：退回回执仍然有效并保留 `retain` 字段凭据；同案新材料（新指纹）只能以补送形式递交，表单携带原退回回执编号，绑定新确认的申请分支；原回执与补送回执在索引中同时可查。

## 代办命令

```bash
npm run agent -- sync                       # 拉取当前阶段来件并与门户回执对账，列出动作与阻塞
npm run agent -- draft <record>             # 仅填草稿（不签署、不递交）
npm run agent -- submit <record>            # 策略放行才递交；补送场景自动绑定原退回回执
npm run agent -- reconcile                  # 重开对账：每份资料当前状态与可否重交
npm run agent -- lookup <回执号>            # 反查受理时按各角色确认的材料
npm run agent -- edit <record> <field> <值> # 登记经办人手工修改
```

环境变量：`PORTAL_URL`（默认 `http://127.0.0.1:4100`）、`AGENT_STATE`（默认 `./.agent-state.json`，已 gitignore）、`HEADED=1` 显示浏览器窗口。
