# 联合数据登记的确认页代办的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。先执行 `npm ci`，再执行 `npx playwright install chromium` 准备 Chromium。

执行 `npm test` 检查合成来源和浏览器页面。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

服务地址下的 `/filing` 为联合登记受理表，`/filing/receipts` 为递交查询。跨区选择会刷新可见表单分支与签署确认格。新递交先进入处理中；推进来件阶段后查询页可显示受理结果。模拟受理记录存在服务进程内，重启可清空本地练习数据。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/intake` | participants 中每行给角色、门户统一编号和来件称呼。fingerprint 由委托方发出，用来绑定签署。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。
